# 4.0 Card Desc Specification (v1, 2026-08-26)

Mirror of the Notion page "4.0 card desc 书写规范 v1" (OD workspace, under `OD`). The desc is both the
design document and the prefab configuration sheet: every keyword maps 1:1 to a GameEvent trigger,
an Effect method, or a target predicate. Chinese keywords below are data (the actual desc language);
this document is the engineering-side reference.

Source data: Notion `4.0 card database` (90 rows as of 2026-09-01: 86 active + 4 backup). Engine status verified against
the codebase on 2026-08-26 (attack-attribute redesign, phase 3).

## Sentence Grammar

```
[trigger][：][cost,]effect-clause[；effect-clause]*
```

- Omitted trigger = 揭晓时 (OnMeRevealed), the most common case.
- Clauses execute in written order, separated by 「；」.
- A cost/gate clause leads, separated by 「，」: `放逐1友方信徒，埋葬2敌方非生物`
  (if the cost cannot be paid, later clauses do not run).
- Plain sequential effects with no gating also use 「；」.

## Revive & Awaken (ratified 2026-08-26)

- 复活 = grave → deck top. 延迟复活 = grave → just before the start card (with no other
  interference it is revealed last this round; same landing slot as the R2 bounce).
  延迟复活 is a revive variant, not a separate mechanism.
- 苏醒 = "when revived"; fired only by revive effects — never by Stage or bounce.
- Selection: only cards with `index < startCardIndex`; excludes passive cards (never
  revivable) and neutral cards; exiled and reveal-zone cards can never be revived;
  empty grave = fizzle.
- Bounced (回响/life) cards land above the start card, never enter the grave, and
  cannot be revived.
- On revive: raise onMeRevived (苏醒) + faction revive events + per-round revive counter.
- Prerequisite: remove or comment out the legacy Revive remnants (`StatusEffect.Revive`,
  `CheckCost_Revive`, related display strings) to avoid confusion with the new mechanic.
- 延迟复活 landing slot = the R2 bounce slot (queue tail, index = startCardIndex + 1) —
  the bounce positioning logic is directly reusable.
- Terminology: when the target is in the grave, always write 复活, never 置顶 — the
  believer token's "stage 1 friendly" is 复活1友方, and "stage the enemy curse" is
  复活敌方诅咒. 置顶 is reserved for pulling from the unrevealed deck.

## Passive Cards (ratified 2026-08-26)

> Engine status: ✅ implemented 2026-08-29 (plan: plans/plan-4.0-passive-cards-2026-08-29.md) —
> placement (re-pinned below the Start Card on every shuffle, ShuffleOrderOverride included)
> + immovability (isPassive excluded from Bury/Stage/Delay/Exile/Revive selection pools).
> Always-on listeners and per-event firing ride on the existing event model with no extra
> engine code. The 14+1 RELIC_* card configs land in step 5; several depend on step-4
> mechanisms (round-end event, attack-times grant, attack resolver sources, BLOOD_PACT
> pipeline rewrite, DEATH_KNELL 遗言触发 verb, TAINT adjacency predicate).

- No separate zone: a passive is a normal card carrying an `isPassive` marker.
- Placement: on every shuffle (including combat start) it is placed after the start card
  (index < startCardIndex, grave side); it is never revealed, takes no reveal slot, and
  costs no fatigue.
- Immovable: bury / stage / delay / exile / revive and any other displacement effects
  fail on it (excluded from movement-effect selection pools).
- Always on: its effects are permanent listeners that fire whenever their condition is
  met (Linger-like, but with a fixed position and no way to leave).
- **Per-event firing (ratified 2026-08-28)**: a passive fires on EVERY matching event —
  no per-round cap, and it is NOT a once-per-own-reveal check. `被动：每次友方攻击，生成1信徒`
  generates one believer per friendly attack event.
- Still a card: it can be enhanced, counts toward grave counts (e.g. 墓地每有1卡), and
  can be read by other cards' predicates (e.g. 攻击力=友方最高攻击力). Value effects do
  not exclude passives — only movement effects do.
- Analogy: a roguelike relic, but carried as a card and participating in card
  interactions.

## Target Predicate Grammar

```
[count][faction][predicate]卡
```

- Faction: 友方 / 敌方; omitted = either faction.
- Predicate: 生物 (= any card with attack, incl. 0) / 非生物 / 信徒 / 诅咒 / 遗言 /
  normal / uncommon / rare / 攻击力最高 / 攻击力最低 / 攻击次数最多.
- Omitted predicate = random (ratified 2026-08-26: no player choice points in combat).
- `自身` = this card; `该卡` = the target of the previous clause.
- Engine support: tag / typeID / isMinion filters ✅; max-attack only on Stage 🟡;
  rarity and 生物 predicates ❌.

## Value Sources

- Fixed: `强化1友方`
- Self attack: `每有1攻击力，埋葬卡组顶1卡`
- Counter: `墓地每有1友方，埋葬1敌方` / `攻击力=本回合放逐的信徒数量`
- Reference: `攻击力=该卡攻击力`

## Extended Constructions (ratified 2026-08-28)

Constructions used by the Notion 4.0 card database (90 rows as of 2026-09-01) that were not covered by the
original keyword tables. Semantics below are ratified; engine status is as of 2026-08-28.

### Distribution Semantics of 强化N

- `强化N[target]` = ONE random target matching the predicate gets +N attack. N is always the
  amount, never the target count — this applies to the whole table, not only curses:
  `强化4敌方诅咒` = one random enemy curse +4; `强化2友方` = one random friendly +2.
- Strengthening several cards by +1 each needs an explicit multi-target phrasing (TBD — no
  card currently uses it).
- `额外强化` continues on the SAME target as the previous clause (该卡 semantics; no re-roll).
  DETERIORATION `强化2敌方诅咒；敌方诅咒每有3攻击力，额外强化1` = one random curse +2, then that
  same curse +1 per 3 attack it has.

### Triggering Deathrattles

- `触发X的遗言` (LAST_RITES `遗言：触发其他友方遗言`, RELIC_DEATH_KNELL `友方苏醒时：触发其遗言`):
  the target card must be in the GRAVE; triggering runs its deathrattle clause(s) while the
  card stays in the grave (no movement, no bury event).
- `遗言触发两次` (RELIC_REQUIEM, threshold `本回合埋葬5友方时`): once the threshold is met,
  ALL friendly deathrattles trigger twice for the rest of the round.

### Granting Effects (给予)

- `给予N[目标]：遗言：…` (DEATHBED_GRANT, RELIC_UNDYING_WILL): the granted deathrattle is
  PERMANENT for the battle — it survives shuffles and is lost only when the target is exiled.

### Swap (交换)

- `交换1友方生物和敌方生物` (SOUL_SWAPPER): the two cards swap DECK POSITIONS; factions do not
  change. A swapped friendly creature may be revealed earlier/later as a result.

### Grave Attack (让墓地X攻击)

- `让墓地1友方攻击` (GRAVE_PUPPETEER): the card stays in the grave and immediately resolves
  one attack at its current attack value; attack events fire normally (有卡攻击时 etc. respond).

### Adjacency (相邻时)

- `友方信徒与敌方诅咒相邻时` (RELIC_TAINT): checked after EVERY deck-order change (bury, stage,
  revive, shuffle, reveal). 相邻 = the two cards' logical deck indices differ by exactly 1.

### Grave Aura

- `墓地中的生物攻击力+1` (RELIC_GRAVE_LORD): a continuous aura — while this card is in the
  grave, all grave creatures (ITSELF included) get +1. Since passive cards are never revivable
  and return to the grave after every shuffle, the aura is effectively permanent.

### Effect Override (效果变为)

- `信徒效果变为：…` (RELIC_RIFT_OVERRIDE): permanently rewrites the effect of ALL believers,
  including believers generated after this point in the battle.

### Damage Pipeline Rewrite

- `友方攻击不再造成伤害，而是强化等量敌方诅咒` (RELIC_BLOOD_PACT): each attack SEGMENT converts
  independently (攻击xN = N conversions of the per-segment amount); attack events still fire
  normally (RELIC_HIVE / RELIC_ATTACK_HEX still respond).

### Nested Triggers

- A trigger may nest inside another trigger's clause: `遗言：回合结束：置顶…` (FINAL_ESCORT) is
  legal. The inner trigger is a ONE-SHOT deferred listener — when the outer trigger fires, the
  inner clause waits for its timing, executes once, and is removed. (FINAL_ESCORT = after this
  card is buried, at the end of this round, stage 1 highest-attack friendly creature.)

### Predicate Extensions

- ~~`除了[X]` exclusion syntax (WEAKENING_FIELD)~~ (Obsolete 2026-09-04: WEAKENING_FIELD desc is
  now `所有生物本回合攻击力-1` — the exclusion was dropped.)
- Tag reference vs state wording (ratified 2026-09-01; full-width 【】 switched to ASCII `[ ]` on
  2026-09-04 — RobotoCondensed-Regular SDF lacks the glyphs): `[X]` brackets refer to cards
  carrying tag X (e.g. RIFT_SHEPHERD `复活 <b>1</b> 张tag为[<tag:Believer>]的友方卡`). A game
  STATE is written in plain words WITHOUT brackets — e.g. ELITE_REVIVER `复活1被强化友方生物`
  targets a friendly creature that has been strengthened, whatever its tags. (Supersedes the
  2026-08-28 `【被强化】` predicate ruling below.)
- Trigger wording: `每复活1友方，…` is NOT a legal trigger — rewrite as the standard trigger
  `友方苏醒时：…` (RELIC_SOUL_TAX desc updated accordingly 2026-08-28). `每X` remains valid as
  a value source only (e.g. `攻击力=本回合放逐的信徒数量`).

## Hard Rules

1. Terminology unification: only 卡组顶 / 遗言 / 强化
   (banned: 牌堆顶, 牌组顶, 亡语, 增强).
2. Arabic numerals; multi-hit is `攻击x2` (half-width x); ATK=0 lives in the ATK column,
   not in the desc (no more `攻击（0）`).
3. The `被动：` prefix and the 被动 tag must both be present; a mismatch is a data error.
4. The desc carries mechanics only; rationale and tuning notes go to `side note`.
5. One card, one desc line, no line breaks.

   `HasAttackDisplay` is false at 0 with no resolver.)

## Decisions (ratified 2026-08-28)

2. 强化N[target] = one random target +N, table-wide (N is amount, not target count).
3. 额外强化 continues on the same target as the previous clause.
4. 触发遗言 targets grave cards only; the card stays in the grave.
5. 遗言触发两次 (RELIC_REQUIEM) = all friendly deathrattles twice for the rest of the round.

## Decisions (ratified 2026-09-01)

Tag vocabulary iteration on the Notion 4.0 card database.

1. Tag 被强化 renamed to 强化反应 (the old name was being used for multi-attackers). The
   trigger prefix renames with it: `强化反应：` (was `被强化：`), still OnMeGainedAttack.
   Descs updated: UNDYING_WARRIOR, COMBO_STARTER, SNOWBALL.
2. 强化反应 tag only on cards whose desc mentions it — trigger form `强化反应：`
   (UNDYING_WARRIOR / COMBO_STARTER / SNOWBALL) or reference form `【强化反应】`
   (WEAPON_SPIRIT). Removed from the 12 other cards that carried 被强化.
3. WEAPON_SPIRIT desc: `被动：友方生物触发【强化反应】时：强化1该生物` (tags 强化 / 强化反应 /
   被动).
4. ELITE_REVIVER's `【被强化】` meant the STATE, not the tag: rewritten
   `复活1被强化过的友方生物`. Notation rule: `【X】` = tag reference; plain wording = state.
5. New tag 多次攻击 for cards with `攻击xN` (N≥2) in desc (9 cards, incl. conditional forms
   like `遗言：攻击x2`). `攻击次数+N` grants and the `攻击次数最多` predicate do NOT qualify.
6. 每复活1友方 is not a trigger — rewritten to 友方苏醒时： (RELIC_SOUL_TAX desc updated).
7. Believer→复活 exemption removed: 生成信徒 ≠ 复活. The 10 believer-generator cards
   without a 复活 keyword in desc lost the 复活 tag (RIFT_ACOLYTE / RIFT_STRIKER /
   RIFT_INSECT / RELIC_HIVE / SWARM_CURSER / RIFT_HATCHERY / MASS_SACRIFICE /
   SWARM_QUEEN / RIFT_PRIEST / RELIC_TAINT); desc carriers (REVIVE_SUMMONER /
   RIFT_MEDIUM / RIFT_SHEPHERD / RELIC_RIFT_OVERRIDE) keep it. Supersedes Decisions
   2026-08-26 #2. (Axis-link note: 复活×信徒 fell from 6 to 4. 复活×诅咒 = 8 was re-ratified
   2026-09-01 (caps v2) as three role sub-chains counted from desc mechanics, never from raw
   tag overlap — A 复辟载荷 ≤4 (3+1 backup, internal to the 复辟 single axis), B 诅咒揭晓→复活
   ≤2 (2), C 双载荷 ≤2 (2, the only true bridge). Caps v2 live on the Notion axis page; the
   pool-audit skill counts bridges by role.)
8. Tags strictly aligned to desc effects: response / counter / predicate mentions keep
   their keyword tags (RELIC_TALLY 埋葬 / DEATHBED_GRANT 埋葬 / RELIC_DEATH_KNELL
   苏醒+遗言 / EXILE_BERSERKER 放逐 / CURSE_EATER 诅咒 / REANIMATOR 复活 /
   RIFT_SHEPHERD 信徒 unchanged); grave-counter cards (GRAVE_GIANT / RELIC_GRAVE_CURSE /
   RELIC_GRAVE_LORD) lost 埋葬 — their descs never contain the keyword.
9. `攻击次数+N` grants get NO tag: BATTLE_HORN / COMBO_GRANTER lost 强化 (强化 = attack
   +N; 多次攻击 excludes grants); RELIC_CURSE_HASTE keeps 诅咒/被动.
10. `攻击力翻倍` is tagged 强化 (UNFINISHED_ROBOT; same AttackGiverEffect family).
11. Missed tags backfilled (11 cards): RIFT_ACOLYTE +苏醒, RIFT_MEDIUM +信徒,
    KINGSLAYER / RIFT_GUIDE +埋葬, MIMIC_BLADE / QUAD_STRIKER / WOKEN_BLADE /
    SNOWBALL +多次攻击 (all 9 多次攻击 cards now tagged), SNOWBALL +强化反应+强化,
    RELIC_TAINT / RELIC_RIFT_OVERRIDE +放逐, UNFINISHED_ROBOT +强化;
    FLURRY_REVIVER / ELITE_REVIVER −强化 (predicate/state), REANIMATOR −信徒,
    RIFT_HATCHERY −苏醒 (desc lacks the clause; if the Unity final state is the
    revive-gated dormancy engine, the DESC needs 苏醒, not the tag). 27 cards updated
    and verified via notion-fetch.
